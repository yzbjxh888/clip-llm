# 方向 04 · 一体感与幂等自适应

用 `impeccable` 技能的 arrange / adapt / color-and-contrast 参考出的**单版修正方案**，
不是新方向候选。设计上下文按对话已知：划词查词的桌面词典，读解释与多轮追问，
要「现代简约 + 暖纸感」。

## 立场

界面不再是一堆「贴在背景上的白卡片」，而是同一张纸上靠明度、细线和疏密分出层次；
常用查询方式与其他角度都排成恒定双列紧凑网格，靠字号和行高分主次；
窗口外框随尺寸连续变化且重复调整结果一致，列数始终不变。

## 逐条回应这次的反馈

| 反馈 | 这一版 |
|---|---|
| 不够现代简约、布局一般 | 圆角 10–12 → 6–8；条目去掉外框，只留细分隔线；默认项用一条 2px 陶土细条；标题字重放轻；字号保持不变 |
| 配色 / 背景 / 滚动条没融为一体 | 窗口、输入框、条目、滚动条全部取自同一暖纸色系的 4 个明度；没有纯白块；滚动条 6px、轨道透明、滑块用纸边色，hover 才加深 |
| 其他角度条目间隔过大 | 间距 12px → 6px，行高 56px → 34px，无描边卡片 |
| 其他视角单列浪费空间 | **常用查询方式 + 其他角度都固定 2 列**（任何窗口宽度都不变，也不出现 3 / 4 列），间距 4–8px 随宽度微调；主推荐 42px / 15px、其他角度 34px / 13px，靠大小与强调细条分主次 |
| 外框应随初判界面大小自动**幂等**调整 | 外框内边距与圆角用 `clamp() + cqi` 连续跟随容器宽度；`@container` 只微调间距，**列数始终 2**；JS 的 `ResizeObserver` 只在档位变化时写一次 `data-tier`，档位不变不写 DOM、不重建控件 |

顶部「重排次数 / 窗口内节点数」面板用来验证幂等：把宽度滑到同一档位来回拖，
重排次数不涨、节点数不变。

## 落地到 Qt 时的对应点（已按 04 落地）

- 一体感：`theme_tokens.py` 增加同色系的 `surface_raised` / `surface_hover` / `scrollbar`，
  卡片与输入框不再用 `surface_lowest` 纯白；`QScrollBar` 滑块改纸边色、轨道透明。
- 两处网格：`query_tab.py` 的 `_intent_grid` 与 `_other_grid` **都固定 2 列**，
  `setSpacing` 随宽度在 4–8px 间微调；主推荐 42px / 15px、其他角度 34px / 13px 区分主次。
- 幂等：现有 `_relayout_intents()` 的 `if cols == self._grid_cols: return` 思路扩展成
  「档位」（外框内边距 + 间距一起判断，列数恒定不参与），档位相同直接返回，
  不重复 `addWidget` / 不重建按钮，避免反复 resize 累积或抖动。
- 回归用例折中：`_grid_cols` 仍保留 2/3 宽度档位（`test_intent_grid_adapts_to_width`
  会读它），但按钮摆放固定两列；这样不改动既有测试，也不改业务逻辑。
- `MAX_INTENTS` / `MAX_OTHERS` 上限、业务逻辑、信号、快捷键一律不动。
